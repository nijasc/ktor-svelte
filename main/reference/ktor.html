Ktor settings ​

Every setting of install(Svelte) { }. To pick settings with checkboxes instead, use the configurator.

The values shown are the defaults.

kotlin
install(Svelte) {
    apiPrefixes("/api")
    paramRoutes()
    spaFallback = "200.html"
    notFoundPage = "404.html"
    source = SvelteSource.Classpath
    generateTs = false
    generateTsOutput = null
    apiDocs = false
    apiDocsPath = "/api/docs"
    routing = SvelteRouting.Automatic
    originCheck = true
    hideErrorDetails = true
    apiCompression = true
    allowedOrigins()
    maxApiBodySize = 1048576
    maxJsonDepth = 64
    maxJsonStringLength = null
    sitemap = true
    defaultFavicon = true
    siteUrl = null

    securityHeaders {
        enabled = true
        contentTypeOptions = "nosniff"
        frameOptions = "DENY"
        referrerPolicy = "strict-origin-when-cross-origin"
        contentSecurityPolicy = null
        automaticContentSecurityPolicy = true
    }

    cache {
        immutable = "public, max-age=31536000, immutable"
        html = "no-cache"
        other = "no-cache"
    }

    dev {
        url = "http://localhost:5173"
        mode = DevMode.Auto
        allowRemote = false
        panel = true
        browserLogs = true
    }

    transport {
    }
}
SettingPurpose
apiPrefixesPaths the frontend never answers, and the routes included in generateTs. /api matches /api and /api/x, not /apiary
paramRoutesSvelteKit route patterns such as /items/[id], /docs/[...rest] and /blog/[[page]]. Matching paths get the fallback even when the request does not accept HTML, for example link previews or tests. Paths with a file extension still return 404
spaFallbackPage for client-side routes. Must match the adapter's fallback option. null disables it
notFoundPagePage served with status 404. null disables it
sourceSvelteSource.Classpath, or SvelteSource.Directory(path) to serve a build from disk
generateTsGenerates TypeScript from your routes in development mode
generateTsOutputOutput directory. Defaults to src/lib/api in your frontend
apiDocsServes Swagger UI in development mode. See API docs
routingManual lets you place the frontend with svelte(). See Auth
originCheckRefuses cross-site requests to API paths for every method except GET, HEAD, OPTIONS and TRACE. See API request guards
buildHeaderSends the frontend build fingerprint on API responses as X-Ktor-Svelte-Build, so the client can notice a deploy. On by default
maxJsonDepthRefuses JSON request bodies on API paths that nest deeper than this, with 400. 64 by default, null turns it off
maxJsonStringLengthRefuses JSON request bodies on API paths with a longer string, with 400. Off by default
sitemapServes a generated /sitemap.xml and /robots.txt when the build has none. On by default. See Sitemap and robots.txt
siteUrlPublic address used in the sitemap, such as https://example.com. null takes it from the request
defaultFaviconServes a ktor-svelte favicon while the app has none of its own. On by default. See Default favicon
requestIdsGives every request an X-Request-Id, keeps one sent by the client and logs it with unhandled errors. On by default
hideErrorDetailsAnswers unhandled exceptions in production without their message. See API request guards
apiCompressionCompresses API responses of 1 KiB or more with gzip, deflate or zstd. On by default. See API compression
allowedOriginsExtra origins, such as https://admin.example.com, that may write to the API
maxApiBodySizeLargest request body on API paths, in bytes. null disables it
securityHeaders.enabledSends security headers. false turns all of them off. See Security headers
securityHeaders.contentSecurityPolicyYour own policy, sent unchanged on every response. null uses the automatic policy
securityHeaders.automaticContentSecurityPolicySends a strict CSP built from the inline scripts of each HTML page. Extend it with allowCspSources(directive, sources)
publicConfig(value)Values for the frontend. publicConfig { ... } reads them again on every request in development. See Runtime config
cacheCache-Control values for _app/immutable/**, HTML pages and other files
dev.urlVite URL. The KTOR_SVELTE_DEV_SERVER environment variable overrides it
dev.modeAuto follows Ktor's development mode. Always and Never force it
dev.allowRemoteLets other machines use the dev proxy, and lets dev.url point at another machine. Off by default
dev.browserLogsSends browser console output, uncaught errors and unhandled rejections from pages proxied from Vite to the app's log. On by default
dev.panelShows a panel of recent API calls, with status, timing and validation errors, on pages proxied from Vite. On by default. See Dev workflow
transportJSON, XML and compression. See Transport

A route of yours such as get("/{slug}") beats the frontend. That is intended, but it can hide pages.

ETags are content hashes from the manifest, so 304 responses are cheap and stay valid across restarts. If you set adapter({ precompress: true }), the .br and .gz files are served based on Accept-Encoding. Files the adapter did not compress, such as those from static/, are gzipped by svelteBundle unless you set precompress = false. .zst files next to them, for example from a Vite compression plugin, are bundled too and preferred for browsers that accept zstd, since they decompress faster.

If the frontend build is missing, the app fails at startup in production with a message explaining what to do. In Ktor development mode it logs a warning instead, and frontend routes return a 503 explaining the problem.
