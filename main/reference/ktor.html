Ktor settings ​

Every setting of install(Svelte) { }, grouped by topic, with its default. To pick settings with checkboxes instead, use the configurator. To see the settings your app really runs with, run ./gradlew svelteConfig.

Ktor plugin

All defaults at a glance ​

The values shown are the defaults.

kotlin
install(Svelte) {
    apiPrefixes("/api")
    paramRoutes()
    spaFallback = "200.html"
    notFoundPage = "404.html"
    source = SvelteSource.Classpath
    generateTs = false
    generateTsOutput = null
    apiDocs = false
    apiDocsPath = "/api/docs"
    routing = SvelteRouting.Automatic
    loginPage = null
    statusEndpoint = false
    internalAccess { }
    healthEndpoint = false
    warmUp()
    originCheck = true
    hideErrorDetails = true
    apiCompression = true
    mailer = null
    inlinePublicConfig = true
    buildHeader = true
    requestIds = true
    accessLog = false
    publicBuildInfo = false
    defaultTimeZone = "UTC"
    allowedOrigins()
    maxApiBodySize = 1048576
    maxJsonDepth = 64
    maxJsonStringLength = null
    sitemap = true
    defaultFavicon = true
    siteUrl = null

    securityHeaders {
        enabled = true
        contentTypeOptions = "nosniff"
        frameOptions = "DENY"
        referrerPolicy = "strict-origin-when-cross-origin"
        contentSecurityPolicy = null
        automaticContentSecurityPolicy = true
    }

    cache {
        immutable = "public, max-age=31536000, immutable"
        html = "no-cache"
        other = "no-cache"
    }

    dev {
        url = "http://localhost:5173"
        mode = DevMode.Auto
        allowRemote = false
        slowApiCall = 500.milliseconds
        panel = true
        browserLogs = true
        refreshAfterRestart = true
        errorOverlay = true
        startupTiming = true
        catchEmails = true
    }

    rateLimit {
        enabled = true
        apiWrites = 120
        period = 1.minutes
        algorithm = RateLimitAlgorithm.FixedWindow
    }

    transport {
    }
}

Route.svelte() ​

With routing = SvelteRouting.Manual, you place the frontend in your own routing. Call install(Svelte) first.

CallWhat it does
svelte()Serves the frontend for every path under this route. Pages get private caching, so shared proxies do not keep them
svelte(public = listOf(...))Serves only the listed paths, with normal caching. A path ending in /* covers everything below it. A listed page also answers with the other trailing slash, so /login/ redirects to /login instead of asking for a sign-in
kotlin
routing {
    svelte(public = listOf("/login", "/_app/*"))
    authenticate("session") {
        svelte()
    }
}

The public list must include your login page and /_app/*, or the login page cannot load. In development mode, svelte(public = ...) also opens the paths Vite needs, so hot reload works on your login page. The files of an installable app, such as /service-worker.js and /ktor-svelte/*, stay public too, since a browser fetches them without a session. See Auth.

Path parameters ​

call.pathParameter<T>(name) reads a path parameter in the type you need, so a route does not parse it by hand:

kotlin
get("/api/notes/{id}") {
    val id = call.pathParameter<Int>("id")
    call.respond(store.create(Note(id, "x")))
}
TypeReads
StringThe text as it is
Int, LongA whole number
UUIDA UUID
An enumA constant by name, in any case

A value that does not fit, such as /api/notes/abc, ends the request with Ktor's NotFoundException: the address names nothing, so the answer is 404, through your StatusPages if you have one. Asking for a parameter the route's path does not have, or for a type it cannot read, is a mistake in the route and fails with a 500 that says so.

Good to know ​

  • A route of yours such as get("/{slug}") beats the frontend. That is intended, but it can hide pages. The app logs it: "the Ktor route GET /about hides the frontend page about.html. Move the route or rename the page."
  • ETags are content hashes from the manifest, so 304 responses are cheap and stay valid across restarts.
  • If you set adapter({ precompress: true }), the .br and .gz files are served based on Accept-Encoding. Files the adapter did not compress, such as those from static/, are gzipped by svelteBundle unless you set precompress = false in Gradle. .zst files next to them, for example from a Vite compression plugin, are bundled too and preferred for browsers that accept zstd, since they decompress faster.
  • If the frontend build is missing, the app fails at startup in production with a message explaining what to do. In Ktor development mode it logs a warning instead, and frontend routes return a 503 explaining the problem.
  • ktor-svelte installs Ktor's RequestBodyLimit and RateLimit itself. To use your own, set maxApiBodySize = null or rateLimit { enabled = false }. The same goes for ContentNegotiation and Compression when you use transport { }.
